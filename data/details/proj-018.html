📱 手机竖屏下的两个真实病因

用户反馈网页端在手机竖屏下项目与视频显示异常。诊断后发现这不是一个问题，而是两个独立病因叠加：一个是 CSS 布局收缩失效，一个是数据加载没有兜底。

病因 1

导航栏被压成竖排

.nav-links 是 flex 容器但没设 min-width: 0，而 flex 子项默认 min-width: auto，宽度压不下去，链接文字被挤成一列竖排。

  • 关于 / 技能 / 项目 / 视频 / 联系 各占两行
  • 768px 断点原本只改 padding 与 font-size，没处理收缩
  • 修复：min-width:0 + flex:1 1 auto + overflow-x:auto
  • 子项 flex:0 0 auto、链接 white-space:nowrap、logo flex:0 0 auto
病因 2

板块双双空白

项目与视频全靠 fetch('data/projects.json') 驱动渲染，国内访问 GitHub Pages 不稳时请求失败，两个板块同时空白。

  • 症状：整页只剩导航与个人介绍
  • 根因：数据渲染对网络请求零容错
  • 解法：内联数据 + 三级兜底
  • 额外补 420px 超窄屏断点
修复

三级兜底渲染链

把「一次 fetch 决定成败」改成三级降级，任何一级可用都有内容渲染。

  • ① 内联数据（立即渲染，零网络依赖）
  • ② fetch 最新（仅内容变化时重绘，避免闪烁）
  • ③ localStorage 缓存 → 才报错
  • 副作用治理：initEffects 拆一次性与可重复，renderProfile 加守卫
验收

CDP 直连做移动端仿真

Selenium 与当前 Edge 版本协议不兼容，直接降一层用 Chrome DevTools Protocol 直连，拿到了比截图更硬的量化指标。

  • headless Edge + remote-debugging-port + websocket
  • Emulation.setDeviceMetricsOverride 模拟 390×844 / DPR 3
  • Runtime.evaluate 注入探针取 DOM 度量
  • Page.captureScreenshot 留存截图

💡 验证方式很关键：不能整体断网——那样连 HTML 都加载不到，测不出数据层的降级能力。正确做法是用 Network.setBlockedURLs 精准只阻断 projects.json，再确认控制台正确告警降级、卡片仍全部渲染。

🛠️ 自建移动端验收工具链

Selenium 4.49 + msedgedriver 与 Edge 156 组合下 set_page_load_timeout / get 一律报 WebDriverException: unhandled request——协议层不兼容，不是配置问题。往下退一层比死磕更快。

🔧 关键实现要点

环节 做法 踩坑
启动浏览器 msedge --headless=new --remote-debugging-port=9333 --user-data-dir 目录必须先建
取调试地址 urllib 读 /json/list 拿 webSocketDebuggerUrl 无需额外依赖
建立连接 websocket.create_connection(url) 必须 suppress_origin=True
模拟手机 Emulation.setDeviceMetricsOverride width 390 / height 844 / dsf 3 / mobile true
注入探针 Runtime.evaluate 取 DOM 度量 探针内不能用顶层 return
Python 环境 Python310 + websocket-client 内置 Python 未装 selenium

💡 可复用经验：探针代码必须包成 (() => { ... return out; })()，否则在 Runtime.evaluate 里用顶层 return 会被当作语法错误。这一条在写自动化探针时几乎必踩。

📌 三条可迁移的结论

原则 1

静态站上任何依赖 fetch 的板块都要有兜底
否则网络一抖就是白屏

原则 2

CSS flex 移动端问题八成是漏了 min-width: 0
flex 子项默认 min-width:auto 压不下去

原则 3

工具不兼容时往下退一层
Selenium → CDP 直连，比死磕更快
