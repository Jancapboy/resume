🩺 把运维巡检做成一个能直接挂进 CI 的命令

运维巡检工具最常见的失败方式不是「检查得不准」，而是检查结果没法被脚本消费 —— 要么只能人眼看表格，要么退出码永远是 0。这个工具的目标很窄：指标全部当场真采集，结论全部编码进退出码，让 opsctl check 能直接当 CI 的一步。

采集

只用 Node 内置能力

采集层不引任何第三方 HTTP 库，os / fs / net / tls / fetch 就够了；运行时依赖只有 commander ^12.1.0 与 chalk ^5.3.0 两个。TypeScript 5.6 开 strict 与 noUncheckedIndexedAccess —— 采集层大量处理 undefined，让类型系统兜住。

  • 8 个 TS 源文件共 1286 行：cli 233 / runner 226 / system 213 / render 162 / network 143 / types 132 / config 89 / rules 71
  • 构建为 tsc → dist/，再用 postbuild 注入 shebang 与 Unix 可执行位
  • 配置与阈值全部外置 JSON，含 cpu / memory / disk 的 warn/crit 与 sampleMs
退出码

四档语义，实跑复现

退出码是这个工具的对外契约：0 = PASS / 1 = WARN / 2 = FAIL / 3 = ERROR。四个分支不是写在文档里的定义，而是本轮逐个实跑验证过的行为。

  • 全部指标正常 → 退出码 0（用放宽容量的配置实跑确认）
  • 触发 WARN 阈值 → 退出码 1（用随仓库的低阈值样例实跑确认）
  • 任一项 FAIL → 退出码 2；配置文件不存在 → 退出码 3
  • watch 模式末轮状态同样作为退出码，便于脚本串联
检查项

12 项，全部当场真采集

CPU 使用率 / 内存 / 4 个磁盘分区 / 系统运行时长 / 2 个 HTTP 端点 / 2 个 TCP 端口 / TLS 证书剩余天数 —— 每项都带自己的阈值与 detail 字段，失败时给出可读原因而不是一个布尔值。

  • 报告 JSON 含 hostname、platform、durationMs 与逐项 id / name / group / status / value / detail / threshold / message
  • summary 字段给出 total / pass / warn / fail / skip 计数，便于脚本直接判断
  • 失败项会额外给出根因，例如「不可连接」而非笼统的「检查失败」
平台差异

Windows 上那些不成立的直觉

跨平台工具的真正难点不在写代码，而在某些 API 在某个平台上静默返回错误值。这几处都是实测发现后才换的实现。

  • CPU 使用率不能用 os.loadavg() —— Windows 上恒为 0，改用两次 os.cpus() 累计时间差
  • Windows 磁盘容量走 Get-CimInstance Win32_LogicalDisk，POSIX 侧用 df -k
  • TLS 证书实测腾讯云域名剩余 40 天、到期 2027-01-06、签发机构 DigiCert

📊 四个退出码分支的实测记录

下表每一行都是实际运行 opsctl check 后读回的真实退出码，不是设计文档里的约定。

🧪 退出码语义与触发条件

退出码 语义 实测触发方式 本轮验证结果
0 PASS 全部指标低于 warn 阈值 ✓ 实跑确认
1 WARN 任一项落在 warn 与 crit 之间 ✓ 实跑确认
2 FAIL 任一项超过 crit 阈值或探测失败 ✓ 实跑确认
3 ERROR 配置文件不存在等运行期错误 ✓ 实跑确认
watch 模式 末轮状态作为退出码

💡 为什么 ERROR 要单独占一档：「检查不通过」和「根本没检查成」是两件事 —— 配置写错导致什么都没跑，如果也返回 2，CI 里就会出现「体检失败」的假象，让人去查根本不存在的问题。

🖥️ 12 项检查与各自的阈值口径

类别 检查项 阈值口径 失败时的可读原因
system CPU 使用率 ≥ 70% 告警 / ≥ 90% 严重 输出物理核心数与 CPU 型号
内存使用率 ≥ 80% 告警 / ≥ 92% 严重 已用 / 总量（GB）
磁盘使用率（逐分区） ≥ 80% 告警 / ≥ 92% 严重 可用 / 总计
net HTTP 端点 × 2 期望状态码落在 200 区间内 fetch failed / 超时
TCP 端口 × 2 端口应处于监听状态 ECONNREFUSED + host:port
TLS 证书 ≤ 21 天告警 / ≤ 7 天严重 剩余天数 + 到期日 + 签发机构
system.uptime 仅供参考 运行时长

💡 阈值必须可配置：同一台开发机和一台 64 核构建机，内存告警线不可能一样。所有阈值外置为 JSON，init 命令能生成一份带默认值的模板。

🪨 真正踩过的坑

这些不是「注意事项」，是写错之后会静默给出错误结论的地方。

静默错误

os.loadavg() 在 Windows 上恒为 0

这是最典型的「不报错但结果是错的」：os.loadavg() 在 Windows 上返回 [0, 0, 0]，如果直接拿它当 CPU 使用率，工具会永远报 0% —— 一个看起来健康的假象。

  • 改用两次 os.cpus() 累计时间差计算真实占用
  • 采样窗口可配置（sampleMs），默认 500ms
  • detail 字段同时输出核心数与 CPU 型号，便于核对
平台分支

磁盘容量不能跨平台

Windows 没有 df，POSIX 下 Get-CimInstance 也不存在。两个平台各写各的采集路径，但共用同一套判定与渲染逻辑。

  • Windows：Get-CimInstance Win32_LogicalDisk
  • POSIX：df -k
  • 判定与阈值与平台无关，只换采集实现
终端

中文混排的表格对齐

终端里一个汉字占两列，但 JS 的 String.length 算它是一列。直接用 padEnd 会让含中文的表格整体错位。

  • 自己实现 displayWidth：中文按 2 宽计算
  • 自己实现 stripAnsi：剥掉颜色转义后再算宽度
  • watch 模式有 TTY 就原地刷新（\u001B[2J\u001B[H），非 TTY 降级为追加
可用性

一条命令覆盖四种使用场景

同一个采集内核，四种消费方式：人看表格、脚本读 JSON、CI 读退出码、watch 持续盯盘。

  • check 单次体检 / watch 持续刷新
  • doctor 自检运行环境 / init 生成模板配置
  • --json 机器可读输出 / --save 落盘报告

原则 1

对外契约优先选退出码
机器消费成本最低的信号

原则 2

ECONNREFUSED 比「失败」有用得多
