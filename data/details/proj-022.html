💎 核心命题：把「视觉质感」和「素材产能」拆成两条独立的工程线

这一版的主题升级其实由两件事构成：一是用纯 CSS 令牌写出一套琉璃玻璃材质层，让页面在没有 3D 引擎的情况下也有折射感；二是把 AI 素材的生产从「本地 ComfyUI 工作流」换成「云端应用编排」——因为本地的算力只能出片，出不了可复用的产品图。

材质层

琉璃玻璃令牌

不用 Three.js 也能有折射感——用光谱令牌 + backdrop-filter 把「白光照在水晶上」的色散次序直接编码进 CSS 变量。

CSS 玻璃拟态 CSS 设计令牌
  • css/liuli.css 共 387 行，独立主题层，加载顺序在 style.css 之后
  • 7 色光谱令牌：青碧 #22d3ee → 靛蓝 #6366f1 → 藕紫 #a78bfa → 品红 #e879f9 → 琥珀 #fbbf24
  • 玻璃材质：backdrop-filter: blur(22px) saturate(175%) + 152° 内高光渐变
  • 光谱描边用 ::before 渐变遮罩边框实现：静态 opacity .22 / 悬停 .85
  • Hero 影视层：video + 左侧渐变遮罩保 WCAG 对比度 + 焦散光斑漂移层
产能层

云端应用编排

不用猜参数名，而是逆向出应用入口与节点 ID，再按节点投递参数。编排能力一旦摸清，素材产能就从「等渲染」变成「调参数」。

RunningHub API MJ 图像生成 MiniMax-H3 视频生成
  • MJ 风格文生图：webappId = 2115537275114311682
  • H3 多参考 + 放大生视频：webappId = 2116538861068308482
  • 生图节点：19:aspect_ratio（MJ 命名体系）、10:text
  • 视频节点：167:prompt（运镜）、164:aspect_ratio、163:value（时长秒）、268:value（放大）、238:image（首帧）
逆向

消费级 Key 的真实边界

同一把 Key 调不同模型端点，得到的却是完全不同的结果——先摸清哪些端点根本不开放，再决定走哪条路，而不是在错误路径上反复重试。

  • alibaba/qwen-image-2.0-pro → 1014 Access Denied：标准模型 API 仅限企业共享 Key
  • rhart-image-g-2 → 40310：因合规要求该模型在当前 CN 节点已下线，需前往全球站
  • 结论：消费级 Key 只能走 AI 应用（run-app）路径，不能直连模型端点
  • 同类排查可迁移到任何「多端点 + 多套餐」的平台型 API
产出

素材规格与成本

一套 Hero 素材要同时满足视觉一致、体积可控、移动端可降级三条约束——所以不是出一张图就完事，而是出一整套规格矩阵。

  • hero-droplet.mp4：1280×720 / H.264 / 5.17s / 662 KB，作 Hero 循环背景
  • hero-poster.jpg：1280×720 首帧海报 / 79 KB，作 video poster
  • 移动端降级：hero-poster-sm.webp 960×540 / 36 KB
  • 备用静帧：1920×1077 的 JPG 217 KB 与 WebP 107 KB
  • 原始素材（4.2MB 原图 + 2.3MB 原视频）留在设计目录，不打包上线

📐 素材规格矩阵（全部实测）

规格不是拍脑袋定的，是把「同一套视觉在四种加载条件下都要成立」拆成可交付的文件清单，逐个核对体积与尺寸。

🔧 平台侧与实现侧的踩坑清单

坑 现象 解法
模型端点不可用 1014 Access Denied / 40310 模型下线 改走 run-app 应用路径
aspect_ratio 取值非法 写 16:9 (Standard) 报 805 工作流运行失败 用 MJ 命名体系 16:9 (Widescreen)
提示词超长 qwen 端点报 1007 单次提示词控制在 800 字以内
size 选项会漂移 索引里的列表是旧的 实际支持 1920*1080 / 2048*872 等，以端点实测为准
下载产物失败 沙箱内 curl 走 schannel 失败 改用 Python urllib 正常下载
轮询超时≠任务失败 任务状态查询迟迟不返回终态 以 node rh.mjs task <taskId> 为准，不靠超时判失败
成本 单轮迭代 526 RH 币（生图 46 + H3 视频约 480） 积分 11006 → 10480，失败不扣积分

💡 「失败不扣积分」这条直接改变了迭代策略：既然试错不花钱，就用「多版并列 + 事后挑选」替代「一次定稿」，把参数搜索从串行试错变成并行批量。

📌 三条可迁移的结论

原则 1

平台型 API 先摸边界，再谈调用
端点能不能用比参数怎么传更重要

原则 2

质感可以靠令牌体系实现，不必上引擎
603KB 的 Three.js 换 387 行 CSS

原则 3

降级要出多档文件，不是缩放单图
桌面视频 / 移动静态 / 窄屏小图，三档各出各的
