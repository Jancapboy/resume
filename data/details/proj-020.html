🎲 纯前端架构：引擎层与渲染层彻底解耦

整个应用是纯前端 SPA（React 18 + Vite + Zustand，不引入后端）。关键设计是全局种子化 PRNG + 纯数据 GameState，让「存档 / 复现 / 未来接后端权威结算」成为同一问题的不同读法，而不是三套逻辑。

架构

三层结构

src/engine/ src/state/ src/components/
  • 领域层 engine：types / rng / data / generals / battle / campaign，纯 TS 零 DOM 依赖
  • 状态层 state：Zustand store + StorageAdapter
  • UI 层 components：WorldMap(SVG) / SidePanel / BattleView / MainMenu / Modals
确定性

种子化 PRNG

用 mulberry32 全局种子化随机源，配合纯数据 GameState，保证同一种子必得同一局。

  • 随机源集中在 rng.ts，不散落各处
  • 存档导出导入后状态完全一致
  • 损坏的存档字符串返回 null 而非抛错
  • StorageAdapter 是预留的后端接缝
数据

数值表驱动

所有内容都是结构化数值表，改平衡性只改表、不改逻辑代码。

  • 22 座城池 / 6 大势力 / 56 名武将
  • 8 种兵种（相克关系）/ 10 种地形 / 19 项特技
  • 伤害公式：武力 × 兵种系数 × 适性 × 士气 − 守方防御 × 地形加成，含命中率与暴击
  • 20 项特技分被动（无双/铁壁/神速/反间）与主动（火计/伏兵/疗怨/收军）
AI

战役级决策

势力 AI 不逐城贪心，而是选定一个目标城、集中旗下部队围攻。

  • 攻守用同一套真实战棋规则结算
  • 锁定目标 + 10 回合僵局解除
  • 连续推进 40 回合状态自洽

⚖️ 平衡性由脚本推演，不靠手感

先用推演脚本摸清战棋的力学特性，再据此改 AI 与玩法，而不是反复手动试玩调数值。

📊 推演得到的力学结论

场景 推演结果 带来的设计改动
兵力相等 攻方必胜 AI 改为集中兵力（势力级战役决策）
兵力劣势（1v2） 攻方 0 / 20 胜 玩家侧改为「同城友军合击」
守城战力评估 不能把整个 garrison 算作战力 守城真正参战的是主将所部
最终平衡 玩家合理策略下蜀汉 / 曹魏 / 群雄胜率 60%+ 单局 35~90 回合

💡 最有价值的一条：「守城真正参战的是主将所部」——estimateCityPower 若把整个 garrison 算作战力，AI 与玩家的判断基准就全错了。这条结论是靠推演脚本跑出来的，不是想出来的。

🐛 10 个由脚本与浏览器暴露的真实 bug

这些 bug 没有一个是肉眼可见的，全部由自测脚本或真实浏览器验证捕获。

🔧 典型 bug 与修法

Bug 根因 修法
AI 攻城后守军 faction 未易主 城池归属与部队归属两条路径不一致 抽出唯一入口 captureCity()
攻城后同城出现两支部队 守军残部未解散 改为溃散 / 降伏 / 被俘三分支
战棋布阵颠倒 createBattle 用 playerIsAttacker 决定上下方 玩家永远在下方
玩家 0 胜 AI 攻城用概率判定，玩家攻城走真实战棋 AI 也走战棋，攻守同一套规则
AI 目标反复横跳 每回合重选目标，永远在行军 锁定目标 + 10 回合僵局解除
React Hooks 顺序违规 useMemo 写在条件性 return 之后 浏览器验证捕获，纯 TS 检查发现不了
战棋选不中第一个单位 handleTileClick 开头 if (!unit) return 造成死锁 调整判空时机
SVG 文字拦截点击 城市名点击选不中 加透明点击热区 + pointer-events 内联
economy 通胀 60 回合攒 1.2 万金花不出去 城池产出系数下调
两座城无守将 qingxu / yiling / nanjun 缺武将 补武将，并在自测加「每城守将覆盖」检查

💡 「玩家 0 胜」这一条最值得记：这不是 bug 而是结构性不公平——AI 和玩家走了两套完全不同的结算规则。修法不是调数值，是把两侧统一到同一套规则上。

🔍 验证方式本身也有坑

Playwright 对 SVG viewBox 缩放有兼容问题，element.click() 会误报 "intercepts pointer events"——这会让人误以为是应用 bug。

🧰 验证工具链要点

问题 解法
Playwright 全局安装因权限失败 本地 npm i -D @playwright/cli 后用 ./node_modules/.bin/playwright-cli
SVG viewBox 下 element.click() 误报拦截 改用 page.mouse.click(bbox 中心) 真实坐标点击
每次 CLI 调用后浏览器会话会关闭 一次 run-code 内跑完整个验证流程
纯 TypeScript 检查抓不到 Hooks 顺序问题 必须真实浏览器跑一遍

💡 技术栈实测版本：React 18.3.1 / Vite 5.4.11 / Zustand 4.5.5 / TypeScript 5.6.3 / Playwright CLI 0.1.22，脚本层用 tsx 4.19.2 跑 TS 自测。

📌 三条可迁移的结论

原则 1

种子化随机源 + 纯数据状态
存档 / 复现 / 后端结算统一成同一问题

原则 2

平衡性用推演脚本定，不靠手感
先摸清力学，再改 AI 策略

原则 3

两侧规则必须同源
AI 概率 vs 玩家真实战棋 = 结构性不公平
