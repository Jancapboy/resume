🧭 一张图同时承载设计域与工程域

核心思路是统一图模型：节点可同时是 Frame / Text / Token（设计域）与 Task / Milestone / GPU / 人（工程域），边可同时是 contains / renders / binds（设计）与 depends_on / blocks / occupies / owns（工程）。同一份图 = 唯一事实源，三个视图（统一图谱 / 资源排程 / 设计契约）都是它的投影，而不是三份各自维护的数据。

求解内核

双内核分工

布局与排程用两套完全不同的约束求解器，各自解决自己擅长的问题。

Cassowary OR-Tools CP-SAT
  • Cassowary：驱动约束布局
  • CP-SAT：驱动排程与资源占用
  • 三个领域共用同一求解内核
冲突语义

按数据类型分层，禁止全库一套 CRDT

不同数据类型的并发冲突语义完全不同，强行统一只会把「可自动合并」变成「一律要人工裁决」。

  • 几何 → LWW（后写覆盖）
  • 文案 → 检测到不同 actor 并发修改则标 manual
  • 层级 → RGA（预留）
  • 任务状态 → FSM 状态机
  • 资源 → Lease 服务端仲裁
运行时

事件溯源 + 日志重放

所有写入经 store.commit() 产生不可变事件，状态唯一来源是 materialize(seed, oplog) = 基线 + 日志重放。各端重放同一序列得同一状态，这是 CRDT 的正确形态。

  • OpLog 事件不可变：{id, actor, lam, ts, t, target}
  • FSM 状态机：todo → doing → review → done
  • 非法跃迁 commit 直接拒绝并 emit conflict
  • 关键路径每次写入后重算依赖深度与下游影响量
多端同步

主通道 + 兜底 + 离线队列

端标识放在 sessionStorage（每标签页 = 不同端），主通道走 BroadcastChannel，storage 事件做兜底。

  • BroadcastChannel 主通道
  • localStorage storage 事件兜底
  • 离线时 commit 进 pending 不进 oplog
  • online 事件触发 flush 重放并广播

📅 工期估算：加智能体压不动串行段

这是整个项目最反直觉、也最可复用的结论：并行段可以用并发换时间，串行决策链不行。

结论

12 周 = 并行 5 周 + 串行 9.5 周

  • 可并行段：5 周
  • 串行决策链：9.5 周
  • 即便投入无限子智能体，总工期也只能压到 10 周
  • 加智能体无效的环节：架构决策 / 契约冻结 / 同步内核 / 集成 / 实测
并发上限

4~6 是合理并发数

受本机 10 核 20 线程 + 22GB 内存约束，同时还要跑渲染与依赖安装。

  • 建议可并行并发上限：4~6
  • 再高会因内存争抢反而变慢
  • 依赖安装必须走镜像源 + 去代理

🎨 设计令牌管线：三端共用一份源

用 DTCG 2025.10 + style-dictionary 5.7.1 把设计 Token 编译到 css / wxss / agent 三端，保证同一个色值在三端不会漂移。

🔧 三个真实踩坑

坑 现象 解法
usesDtcg 后取值路径变了 值不在 value 而在 $value 自定义 format 必须按 DTCG 规范取 $value
alias 链被拍扁 引用全部变成硬编码 必须开 options: { outputReferences: true }
wxss 无 :root 小程序根节点是 page，不能复用 css/variables transformGroup: 'css' 可完全复用
CLI 直接跑会崩 npx style-dictionary build 要求 default-export config 对象 改用 node config.mjs（1.1s）

💡 还有一条容易踩的：对比度校验必须用显式配对表（$extensions.contrastPairs），笛卡尔积会产生语义荒谬的假阳性，最后导致 CI 校验被直接关掉——比不做校验更糟。

🖥️ 真实服务器部署：1.9GB 内存下的单端口方案

目标机是腾讯云 ap-shanghai（Ubuntu 24.04.4，内核 6.8，sudo 免密）。真正卡住部署的不是代码，是环境约束。

🧱 部署约束与解法

约束 实际情况 解法
内存仅 1.9GB 可用 894MB 禁 Docker、禁重框架
Web 服务器是 Caddy 不是 nginx v2.11.4，配置在 /etc/caddy/Caddyfile routes/ 片段 = route 级指令
双端口会导致跨源 WebSocket 与页面不同源 aiohttp 单端口 8778
安全组精确白名单 仅 22 / 80 / 13439 / 13440 放行 443 需控制台加白名单
密码认证被禁用 allowed types: ['publickey'] 用指定 ed25519 密钥 + paramiko
访问公网 IP 失败 NAT hairpin 不支持，非故障 走 SSH 隧道内网访问

💡 还有两条易错点：routes/ 片段不能写 site 块（会报 unrecognized directive），sites/ 片段不能写 route 指令（会报 parsed 'handle' as a site address）；Caddyfile 有 admin off，不能 systemctl reload，只能 restart。

📌 四条可迁移的结论

原则 1

并发上限由机器决定，不由 agent 数量决定
10 核 20 线程 + 22GB → 并发 4~6 是甜点

原则 2

串行决策链是工期硬下限
加无限智能体也只能把 12 周压到 10 周

原则 3

字典序分阶段求解 ≈ 免费
别用加权求和近似优先级

原则 4

「能不能交互」用审计数据回答
别辩解，量出输入框与 OpLog 数量
