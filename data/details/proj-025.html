🤖 命题：硬件还没到，软件层必须先能跑能测

客户需求是一台带机械臂的工厂自动取件机器人小车，从货架拿元器件送到指定工位，硬件已采购（KICKPi K7 / RK3576 6TOPS NPU + STM32F407ZGT6 + 扫地机器人底盘轮 + Astra Pro Plus 深度相机 + 360° 激光雷达），但机械臂型号未定、YOLOv8 需自训。
难点不在写算法，而在于：整套系统不能因为「还没装 ROS2」就一行都跑不起来。

决策 1

纯 Python 内核 + ROS2 薄适配层

fpv_core / fpv_scheduler / fpv_bt / fpv_perception 全部不 import rclpy，只有 fpv_core/ros2_adapter.py 负责类型转换。

  • 起因很具体：本机 WSL 是 Ubuntu 26.04，ROS2 官方二进制包尚未支持该版本
  • 要求客户先装 ROS2 才肯验证算法不合理——软件层必须能独立跑起来
  • 配套 scripts/setup_wsl.sh A|B|C：Docker 跑 Humble / 重装 24.04 装 Jazzy / 纯 Python
  • 实测核对：全仓 grep rclpy 只命中 contracts.py 注释、ros2_adapter.py 惰性导入与 real_drivers.py 注释
决策 2

契约层是唯一事实来源

所有类型集中在 fpv_core/contracts.py，各子包一律 import 而不重复定义。

  • Shelf.pose 的语义被固化为机器人停靠位，不是货架本身位置
  • 槽位世界坐标统一由 Shelf.slot_world_position(level, slot) 提供
  • 这个语义一开始理解错了（当成货架本身）→ 机器人站到货架上、物料距离 0.001m、检测全为 0
  • 教训已写进架构文档，避免下一任接手者重踩
决策 3

HAL 用 Protocol，真机与仿真同接口

配置里改一行 backend: sim | real 即可切换底层实现，上层算法一行不改。

  • 所有第三方依赖（pyserial / can / rknn / ultralytics）惰性导入
  • 开发机缺这些库也能 import 全部模块并跑完测试
  • fpv_msgs 提供 4 个 msg + 1 个 srv + 2 个 action 的 ROS2 接口定义
  • 效果：开发机不需要真机也能做全流程回归

🧮 调度内核：四个算法，四个独立的坑

调度层不是「写个队列」那么简单。TaskQueue、Batcher、Allocator、GridPlanner 四个模块各自踩了不同的坑，其中三个是单元测试直接抓出来的。

🔧 调度内核实现要点

模块 实现要点 踩过的坑
TaskQueue 堆键 (-优先级, 创建时间, 入队序号, task_id) 必须补入队序号：created_at 只到微秒精度，批量创建时相同，仅靠它 FIFO 不稳定
Batcher 按货架聚类 → 路径长度估算 → 与逐单执行对比收益 聚类粒度错了会拆散同货架任务，收益反而为负
Allocator 打分 w1/距离 + w2·优先级 + w3·电量健康度（w1=1.0 / w2=0.02 / w3=0.05）；货架与工位独占锁；等待图 DFS 找环 破环时释放持有资源最少的那台车，否则一台车解不开就全线卡死
GridPlanner 八方向栅格 A*，对角启发式可采纳，禁穿角 路径简化的 _line_clear 恒返回 True，直线简化后直接穿过障碍物 → 改为按 resolution/2 步长沿连线采样做真实障碍检测
重试计数 统一为单一计数点 fail() 与 transition() 都自增 attempts → 同一失败被计两次

💡 可迁移经验：「距离」在打分函数里用除法而非减法，是为了让「越近越好」与「优先级/电量越高越好」方向统一为同一个「越大越优」的标量，否则加权求和的符号会互相抵消。

👁️ 感知与指令理解：单目 + 中文口语指令

两个问题都出在「看起来很简单的假设」上：单目相机看不完 3 层货架，以及中文指令不一定含动词「取」。

分层扫描

逐层调整俯仰角扫视

底层物料投影 v=800 已超出 720 视场，单目一次看不完。解法是逐层调整俯仰角，让每层物料落在视野中心再合并结果。

  • 每层用专门为该层高度设计的相机外参（俯仰角随层高增大）
  • 跨帧去重靠稳定 slot_key（货架:层:槽位）
  • 不能用像素位置去重——俯仰角一变，同一物料的像素位置就会移动
  • 实测 5 个货架共 25 个库存位，检出 25 / 25
坐标变换

外参变换必须补齐旋转

base_to_camera 最初只做平移不算旋转，导致物料投影直接飞出视野。

  • 补齐完整 RPY 变换链：世界 → base_link → 相机
  • 俯仰角符号约定（正值俯视）一旦搞反，投影会整体偏到反方向
  • 这类 bug 靠肉眼看截图很难定位，靠「投影点是否落在视场内」反推最快
VLA

中文隐含语义判定

规则解析器先显式匹配动词（取 / 拿 / 抓 / 捡 / 取件 / 拿取），但真实指令常写成「把电容送到工位」——一个「取」字都没有。

  • 补充隐含语义判定：物料 + 货架 + 工位三者齐备即视为取件
  • 另有 VLA id 归一化崩溃：短路访问了不存在的属性
  • 本地 VLM（Qwen2.5-VL）作为规则解析器的补充通道
底盘

到位判定要同时看位置与朝向

曾出现到位朝向偏差 10.8° 超过容差 8.6°，导致 dock 判定永远失败。

  • 改为位置到达后原地微调朝向再判到位
  • 原地转向不计入行驶距离，避免污染里程统计
  • 容差判定：位置误差在容差内 且 朝向误差在容差内，两者都要满足

📌 四条可迁移的结论

💡 沉淀

原则 1

硬件没到位时，先把 ROS2 隔离在薄适配层
核心算法不依赖任何中间件，软件层才能独立跑、独立测、独立交付

原则 2

语义要在契约层写死，并写进文档
「pose 是停靠位还是货架位置」这种歧义，一个词写错会让检测全为 0

原则 3

去重键要选稳定标识，不能选会动的东西
跨帧用 slot_key，不用像素位置——视角一变像素就漂

原则 4

验收数字要能被第三方复现
测试可跑、种子固定、口径写清，结论才站得住
