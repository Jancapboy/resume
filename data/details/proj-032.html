🔮 从排盘工具到双端人格图谱产品

这不是一个「AI 算命 Demo」。项目要同时解决三件工程上彼此耦合的事：把八字 / 五运六气的专业内核做成可复现的纯 JS 计算层、让 React Web 与原生微信小程序共用同一后端与人格数据、按企业主体产出一套能通过形式审查的软件著作权登记材料。最终前端 109 个 ts/tsx 共 22,942 行、后端 34 个 Python 模块 6,000 行、85 张人格卡与 170 张 Q 版形象，线上实测 HTTP 200。

内核

排盘与五运六气：可复现的纯计算层

八字内核完全本地化，不依赖任何在线排盘 API。真太阳时、神煞、大运各有独立模块，神煞规则引擎 v2 忠实复现原版 Python 引擎的 5,940 格 + 120 格校验集，做到零误差。

  • cities.ts 25,956 字节收录 316 个城市经纬度基准，供真太阳时校正
  • calculator.ts 32,663 字节 / luckerhome.ts 15,040 字节，覆盖四柱与大运
  • shensha.ts 18,435 字节，规则引擎 v2 修正地扫 / 死符 / 灾煞 / 月破 / 红艳 / 飞刃等分支
  • solarTerms.ts 89,548 字节节气表 + solarTermTimes.ts 43,433 字节，24 个页面共用
后端

FastAPI 分层 + 流式解读

后端 34 个 Python 模块 6,000 行，按 api / graph / llm / rag / utils 分层；AI 解读走 SSE 流式输出，命理事实与模型结论严格分离。

  • DeepSeek 接入 + RAG 检索，命盘事实作为证据注入而非让模型自由发挥
  • persona-cards.json 85 张人格卡，前端阈值推导（纯型 / 二元 / 三元）取用
  • 微信 AES 消息加解密 wechat_aes.py 184 行、openid 绑定 117 行
  • 群五行地图隐私整改：群 openGId 与个人 field-id 双轨隔离
双端

Web 与小程序共用内核

微信小程序不是把 Web 塞进 web-view，而是把排盘核心移植成纯 JS CommonJS，两端共用同一套计算语义与后端。

  • Web：Vite + React 18 + TS + Tailwind + react-three-fiber + zustand + gsap，24 个页面
  • 小程序原生 7 页（login / webview / badge / dualbadge / findfriend / match / group），14 个 js 共 5,878 行
  • utils/bazi/ 六模块移植（calculator / luckerhome / shensha / palaces / solarTime / solarTermTimes），Node 校验四柱、大运、神煞、真太阳时全对
  • 立体形象 / 画廊支持捏合缩放 minDistance 2.0 ~ maxDistance 6.0

🐛 从编译错误到部署事故：四个真实坑

这些坑都不是「写代码不仔细」，而是平台约束与工程链路的交叉地带：小程序运行时限制、静态资源部署、数组语义、素材管线。

📄 软著材料工程：172 文件 / 42,584 行，19 项断言全绿

小程序与完整版 Web 共用同一代码与后端，属「一个软件、两种运行形态」，一次登记即可。真正的难点不是生成 PDF，而是让申请表、说明书、源程序三份材料里的每一个数字互相自洽。

📌 三条可迁移的结论

原则 1

专业内核先纯函数化
排盘算法不碰 API，Web 与小程序才能共用

原则 2

发布事故优先查产物完整性
「改了没生效」常常是静态资源没上传

原则 3

材料数字只能有一个口径
