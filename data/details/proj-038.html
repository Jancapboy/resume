🎮 231 段视频压成 23 段，还要让 7 个场景都是真几何

按任务书 v1.2 交付的校园恋爱互动叙事游戏，难点不在「做一个游戏」，而在把资产量砍掉一个数量级还不掉质量：整个游戏只需 23 段视频而非 231 段，7 个场景全部是真几何而非背景板，而且每一条链路都有真浏览器点击验收兜着。

剧本

231 节点全部是 YAML 真源

story/ 下 common 12 + c1 70 + c2 72 + c3 77 = 231 个节点，写成 YAML 作为唯一真源，由 build.mjs 的 syncStory() 同步到游戏数据目录 —— 不手写、不复制、不漂移。

  • 任务书 §3.3 要求 ≥150 节点，实际 231，超出 81%
  • 49 个节点带非空 choices，共 98 条选项
  • 12 个分支阈值节点 + 6 个结局（每条线好/普通两档）
  • 7 个场景全覆盖，构建守卫：file_id 重复即构建失败
关键决策

视频互动剧路线

整个游戏只需 23 段视频而非 231 段 —— 循环片按 (场景 × 出场角色组合) 去重，同一组合的所有台词共用一段待机循环片，角色表情改用头像框的 42 张半身差分切换。

  • 3 角色 × 2 套服装 × 7 表情 = 42 张半身差分
  • 另有 6 张按天选服装的全身立绘
  • 角色说话走视频轨，旁白/主角收起立绘显示场景替身
场景

7/7 真实几何

S1 教室 / S2 走廊 / S3 操场 / S4 天台 / S5 图书馆 / S6 美食街 / S7 山水景区全部是程序化几何，全部零贴图零外部请求 —— 断网也能跑，且不踩任何 CDN 依赖。

  • 实测 3,116~9,124 tris、30~51 draw calls
  • 每场含交互点 + 光照预设 + 相机预设，dispose() 后 children=0
  • S6 蒸汽与 S7 水面波纹由 update(t) 驱动
验收

22 项真浏览器点击验收

用 Edge headless + CDP 做真点击（不是接口探测）跑通全链路，报告里 pass=true、errors 与 consoleErrors 均为空数组。

  • 进入游戏 → 逐句推进 → 出选项 → 分支 → 存读档
  • 7 个场景逐个真加载（切场景无异常）
  • 立绘真实渲染 naturalWidth 抽检 + 头像框面部图已解码
  • 视频轨真在播（key 与文件名一致）+ 3D 兜底轨可接管
