🎛️ 核心命题：把简历从「文档」升级成「工作台」

个人站最容易做成千篇一律的渐变卡片。这次的方向是工程感——顶部状态栏、终端档案、指标矩阵、GitHub 实时面板、卡片内可展开的架构分层，配一层真正跑在 GPU 上的液态玻璃折射。但有一条铁律贯穿全程：屏幕上每个数字都必须可验证，接口失败就显示「—」，绝不编造。

渲染层

手写 WebGL2 折射

液态玻璃原本的首选是 Three.js，但 r128 min 版就要 603KB。最终放弃引擎，改用原生 WebGL2 手写 fragment shader——零依赖、零加载体积。

WebGL2 GLSL
  • js/glass.js 共 260 行，单一层全屏 shader 完成全部效果
  • 液态噪声位移 + RGB 三通道色散 + 菲涅尔边缘光 + 玻璃棱边高光
  • 视频作为纹理采样，玻璃层直接折射 Hero 背景
  • 相比 Three.js 方案省下约 603KB 加载体积
降级策略

三道门槛 + 动态降级

WebGL 效果是锦上添花，任何情况下都不能影响功能。所以进入前先过三道设备门槛，运行中再按实测帧率动态降级。

  • 入口门槛：移动端 / hardwareConcurrency < 4 / prefers-reduced-motion → 直接不创建画布
  • 帧率门槛：连续两次采样低于 24fps 才触发降级（单次抖动不误判）
  • 内部渲染分辨率上限 1600×900，视觉无明显差异但帧率稳定得多
  • 降级后 resize() 必须跳过——否则 clientWidth = 0 会把画布缩成 1×1
  • 降级完成后由原生 video 直接呈现，功能不受影响
编排层

动效栈自托管

GSAP 3.13 + ScrollTrigger + SplitText + Lenis 四件套全部自托管，并把「依赖是否存在」的判定从顶层常量改成动态函数——否则脚本加载顺序一变就整段失效。

  • 四件套实测合计 136,859 字节（约 137 KB）
  • studio.js 改 async 加载，内部轮询等待 GSAP（≤3 秒）后启用动效
  • 任一依赖缺失或网络失败 → 自动降级为静态呈现
  • css/studio.css 839 行 + js/studio.js 506 行，含状态栏 / 终端 / 指标矩阵 / GitHub 面板 / 自定义光标 / 架构展开 / 代码块 / 转场
数据层

指标全部可验证

四项指标分两个来源，任何一个拿不到都不许编——前三项来自站点自身数据，第四项来自 GitHub 公开 API，失败即显示「—」。

  • 交付项目 / AI 视频作品 / 技术栈覆盖：来自 projects.json 实时统计（随项目增补自动重算）
  • 公开仓库数：GitHub 公开 API 实测 27 个
  • 语言分布实测：Python 13 / TypeScript 7 / HTML 2 / CSS 1 / Go 1 / Shell 1
  • 近 12 周活跃度用各仓库 pushed_at 聚合——公开 events 接口只覆盖最近 30 天，铺不满 12 周

💡 最危险的一个坑是「用 animation 简写覆盖带入场动画的元素」：它不会报错，只是让元素静默消失——而且移动端媒体查询里的 animation: none 同样致命。规则只有一条：绝不用 animation 简写覆盖带入场动画的元素，流光效果只给没有 .animate-in 的 section 标题。

📌 三条可迁移的结论

原则 1

视觉增强必须自带降级路径
效果是锦上添花，功能不能被它绑架

原则 2

宁可换口径，也不用插值凑数据
pushed_at 替代 events/public，真实优先于好看

原则 3

宁可删掉装饰，也不留死代码
打字机 / 粒子 / 裸 mousemove 倾斜全部物理删除
