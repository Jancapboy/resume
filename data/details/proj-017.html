🌐 三通道并行的交付架构

单一托管通道同时存在会过期与国内访问慢两个风险。做法是并行维护三条通道：GitHub Pages 主站（永久、免鉴权）、EdgeOne 中国站镜像（腾讯边缘加速）、CloudStudio 保底（主备皆失时的最后兜底）。

📊 三条通道实测对比

通道 永久性 鉴权 Range / 206 响应标识
GitHub Pages 主站 永久 免 token 支持 Pages 自动重建
EdgeOne 中国站 永久 需带 token 首访 支持 Server: edgeone makers
CloudStudio 保底 会过期 免 token 不支持 CloudStudio Gateway
视频目录 37MB 三通道同一份产物 两通道支持边下边播 保底通道仅适合纯文本兜底

💡 关键发现：CloudStudio Gateway 的响应头没有 Accept-Ranges，浏览器必须整包下载完才起播；GitHub Pages 与 EdgeOne 都返回 206 Partial Content，配合 +faststart 才能真正边下边播。视频场景下，通道选型的硬指标不是速度而是是否支持 Range。

🔑 访问令牌的生命周期工程

EdgeOne 平台域名没有关闭鉴权的开关，预览令牌约 3 小时过期，且每次部署都会作废旧令牌。这不是一次性的手工活，必须做成自动闭环。

环节 1

同步静态文件

把源站目录的 index.html / project.html / css / js / data / assets 复制到镜像目录，不复制 .git、不做批量删除。

  • 只复制，不在同步环节部署
  • 保留 edge-functions / package.json / .env
  • 部署与令牌刷新拆成两个独立任务
环节 2

部署并抽取新令牌

执行 CLI 部署，部署完成后从产物中抓取新的 eo_token 与 eo_time。

  • edgeone makers deploy --env production
  • ZIP 部署限制：≤50MB，单文件 ≤25MB
  • CLI 全局安装需绕开 Program Files 的 EPERM
环节 3

正则改写配置

用正则替换而非 json.dumps 重写，保持文件原排版，让 git diff 最小、review 时只看令牌两行变化。

  • 只替换 contact.api / contact.mirrorUrl 里的令牌
  • 不重排 JSON，diff 最小化
  • 改完立即做只读验证
环节 4

验证与推送

自建 CookieJar 发起验证请求（默认跟随 302 会丢掉 query 里的令牌造成假性 401），通过后再 git push。

  • urllib 必须自建 CookieJar 才能验准
  • 推送后主站与镜像双通道复测
  • 每 2 小时自动跑一轮

🧨 交付链路的坑

🔧 故障与解法

现象 根因 处置
npm install -g edgeone 报 EPERM 全局目录在 Program Files 需管理员 改装到 PATH 内可写目录
git push 间歇性失败 沙箱内 github.com 主站 CONNECT 502 api/codeload/objects 可达，重试即成功
验证镜像报假性 401 默认跟随 302 丢掉 query 令牌 自建 CookieJar 手动承接
子进程找不到 edgeone / git 内置 Python 的 PATH 被截断 脚本内显式拼绝对路径
API 探测全部 InvalidAction 公开 Action 里没有 Pages 相关接口 改走 CLI 私有 Action 完成部署

💡 架构上的教训：部署动作与令牌刷新动作不能放在同一个任务里——每次部署都会作废当前有效令牌，若两者耦合，刚写入配置文件的令牌会立刻失效，必须等下一次刷新才恢复。

🔑 账号归属与授权链路

站点最初部署在另一个账号下，HR 点 GitHub 图标会跳到另一个号——这是最初部署时未确认归属导致的。最终把仓库整体迁移到本人主账号，并自建授权链路。

  • GitHub MCP 连接器身份正确但只有读权限，create_repository 返回 403，写操作走不了
  • 正解：手写 device flow（public client_id + 轮询 /login/oauth/access_token）拿到令牌，再 gh auth login --with-token 注册
  • gh CLI 支持多账号共存，迁移后主站域名固定为 jancapboy.github.io/resume/，链接永久不变
  • 附带发现：站点上的 GitHub 图标链接与实际部署域名长期不一致，现已对齐
