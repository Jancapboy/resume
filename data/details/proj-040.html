🎮 让摄像头当手柄，但游戏内核一点都不知道

这个项目的难点不在「做一个文字地牢游戏」——那部分很直接。难点在让内核对「输入从哪来」完全无感知：键盘、摄像头、录像回放、脚本注入都只是同一种 InputSource 实现，换输入设备，内核一行不改。

架构

解耦是物理保证，不是口头约定

core/ 层零 import 任何 io/ 的东西 —— 这一点用 grep 逐文件核验过，不是靠自觉维护。输入统一归一化为 GameCommand 判别联合，四种 InputSource 各写各的。

  • 四种实现：Keyboard / Vision / Replay / Scripted
  • 流水线：摄像头 → Python(mediapipe) → JSON Lines → Node CLI 内核 → ANSI 画面
  • 回放与脚本注入天然可测 —— 自动化测试不需要摄像头
算法

视野算法三次选型才收敛

视野计算是纯几何问题，但两种「看起来更优雅」的方案先后失败：递归阴影投射的斜率符号与递归传参写错，对称置换法的象限坐标轴定义自相矛盾。两种方案的共同点是写错了很难看出来 —— 视野只有 1 格，不报错，只是结果不对。

  • 最终方案：射线投射 + 肩部遮挡检查，一次通过
  • 实测空房间半径 8 得到 233 格完美对称圆形
  • 柱子遮挡断言 0 格可见
算法

手势分类的顺序问题

同样是「顺序写错就全错」：初版先判捏合，结果握拳被误判（握拳时拇指也贴着食指）；改用整体伸展度优先，捏合又被误判（其余三指弯曲把平均值拉低了）。

  • 最终解法：用「食指伸展度」单独区分握拳与捏合
  • 捏合判定额外加 index_ext > 1.5 约束
  • 竖拇指必须排在握拳之前判定 —— 否则被握拳分支抢走
交互

三重保险防疯连击

摄像头每帧都识别到手，如果一识别到就执行命令，游戏会疯连击。所以手势必须「松开才能再次触发」。

  • 连续 2 帧确认 + 0.35 秒冷却 + active_gesture 保持态
  • 实测持续握拳 10 帧只触发 1 次
  • 交替 open_palm / fist 8 帧同样只触发 1 次

📊 手势识别与规模实测

下面的置信度与触发次数都是实跑读数，不是标称值。

✋ 四类手势 + 指向四方向

手势 判定依据 实测表现 踩过的坑
fist（握拳） 整体伸展度低 + 食指伸展度低 ✓ 与其他手势互不混淆 最初被捏合分支抢走
pinch（捏合） 捏合比 + index_ext > 1.5 ✓ 需伸食指才能触发 整体伸展度方案下被误判
open_palm（张开） 整体伸展度高 ✓ 用药水 手没认清时最易误判为此

thumbs_up（竖拇指） 拇指伸得远且朝上 ✓ 下楼 必须排在握拳之前判定
指向方向 up / down / left / right 置信度 0.99 ~ 1.00

💡 置信度门槛是必须的：实测低置信张开（0.40）与低置信握拳（0.50）一律被拦截，只有高置信（0.75 / 0.80）才触发；竖拇指 0.50 即可触发 —— 不同手势的门槛不同，因为它们在画面里的特征强度不同。

🪨 这台机器专属的环境坑

这些不是通用问题，而是「在 Windows + 这台机器 + 这个 USB 相机」的组合下才会遇到的坑 —— 全部写进了代码注释与 README。

依赖

mediapipe 1.2.3 移除了 mp.solutions

只剩 Tasks API，需要额外下载 .task 模型文件（实测 7819105 字节 ≈ 7.8 MB）。按旧版示例写会直接报模块不存在。

  • 模型文件随仓库落盘，不依赖运行时下载
  • Python 3.13 没有 mediapipe wheel，必须用 3.12 独立虚拟环境
硬件

摄像头必须预热 2 秒

该 USB 相机（VID_4A54&PID_5231）冷态下第二帧即失败。更隐蔽的是：模型初始化耗时 1~2 秒会挤掉预热窗口，所以必须做「模型就绪后二次预热」。

  • 模型就绪后再预热一次，避免初始化期丢帧
  • 连续失败 30 次自动重开摄像头，自愈不中断
  • 默认 MSMF 后端报 -1072873822，必须切 DSHOW
日志

mediapipe 的日志走 C 层 stderr

Python 层的重定向拦不住它，日志会直接混进 stdout 破坏 JSON Lines 协议 —— 视觉层的输出是逐行 JSON，一旦被日志污染，Node 侧就解析不出来。

  • 用 os.dup2 把 C 层 stderr 重定向到 devnull
  • stdout 只允许出现协议数据
管道

管道下 stdin 有缓冲

键盘手势模拟器要在管道模式下实时响应，sys.stdin.read(1) 会等满缓冲区才返回，看起来就像「按键没反应」。

  • 改用 os.read(0, 1) 绕开 Python 层缓冲
  • Windows TTY 下用 msvcrt.getwch()
  • Node 侧新增 forwardKey() 把按键转发给子进程
