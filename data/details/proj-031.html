🚢 从「零件凭空出现」到「符合装配工艺的全自动物流链」

最初的版本里，船体分段靠 visible=false → true 凭空出现，用户一眼看穿是动画把戏。三轮追问把它逼成真正的工程问题：每个零件一开始就得看得见、按工厂标准定置摆放、由设备一步步吊运装配；零件不能从船底穿上来，必须高空过跨；物流轨迹要符合真实吊装与运输工艺。这个项目把这三轮修正全部固化进一个 Three.js 0.170 单文件，并用无头浏览器探针做了 11 项量化验收。

定置

14 件完整几何副本，2×7 工位陈列

堆场参数 YARD={dx:74,dz:70,z0:96,ncol:7} 定义 2 排×7 列共 14 个定置工位（12 分段 + 艉封板 + 动力舱）。每个工位含定置框 / 液压支墩 / RFID / 状态灯；零件以完整几何副本陈列，而非简化占位块。

  • 副本定位 copy.position = -bboxCenter，材质深拷贝，避免共享材质被落位动画污染
  • 落位时副本隐藏、正式件原位接管，视觉上「被运走的正是这一件」
  • 终态 12 个正式分段全可见、14 件全部安装、堆场副本清零
  • 单文件 94,396 字节 / 1,960 行，three@0.170.0 走 unpkg ESM，零构建双击即跑
工艺

六阶段物理吊装链

不是「物体沿曲线飞行」，而是每一步都有承载关系与载荷转移：门吊脱支墩 → SPMT 落墩 → 主干道折线运输 → 龙门吊四点挂索 → 高空过跨 → 激光对中落位与机器人焊接。

  • ① 堆场门吊挂索、脱液压支墩；② SPMT 6 轴线液压鞍座落墩（6 台）；③ 主干道 z=70 正交折线行驶
  • ④ 坞边龙门吊四点挂索，先建刚性连接再起升脱车；⑤ 高空过跨 SAFE_Y=100，主梁 CRANE_TOP=110 覆盖坞边
  • ⑥ 激光对中落位、脱钩，8 台六轴焊接机器人 + 2 台堆垛机接手
  • 装配顺序 12 步状态机：船坞准备 → 双层底 → 艏部 / 舷侧 → 机库 → 动力舱 → 甲板 → 舰岛 → 精度对中 → 舾装 → 注水 → 交付
设备

按真实船厂配置建模

设备不是装饰模型，各自承担物流链中一个明确的物理动作，数量与作业带尺度相互约束。

  • 悬臂龙门吊主梁 CRANE_TOP=110，覆盖坞边 z=±63 的 SPMT 作业带
  • SPMT 重型模块运输车 6 台，带液压支承鞍座，符合分段载荷传递
  • 四点吊索具 RIG.yard / RIG.gantry：吊梁 + 4 索，挂索后才允许起升
  • 8 台六轴焊接机器人 + 2 台每排一台的轨道堆垛机 + AI 调度中枢面板

🔧 两个「看起来能跑、物理上错的」隐蔽 bug

这两个问题在静态截图里完全正常，只有把时间轴拉长、用探针逐帧采样才能暴露。它们共同说明：三维动画的验收判据必须来自状态量，不能来自画面观感。

📊 修复前后对照

症状 根因 修复
分段滞留平板车上后突然瞬移到吊钩 直接更新 hookY，未先建立吊钩—分段连接 先写 P.attached={dy,...} 建立连接再起升
探针误报「分段穿过船体」 convey 标记在起升完成前就切换，采到低位分段 phase 显式区分 hoist / convey / landing，起升完成后才切阶段

💡 阶段字段 phase 从「渲染用的内部变量」升级为可被自检脚本读取的公开契约，这是把动画变成可验证仿真的一步。

🧪 Edge CDP 无头自检：11 项断言全 PASS

playwright-core 未安装，改用系统 Edge + CDP 协议（Node 内置 WebSocket / fetch，零额外依赖）：本地 HTTP 8899 + 调试端口 9333，把页面挂进真实浏览器上下文后逐帧采样探针状态。

📌 三条可迁移的结论

原则 1

可见性不等于真实性
凭空出现 vs 设备吊运，差别在承载关系而非画面

原则 2

先建连接，再施力
挂索 / 落墩这类动作有严格先后，顺序错了就穿模

原则 3

验收读状态，不读截图
11 项断言全部来自探针数值，截图只作辅助
