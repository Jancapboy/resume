🏷️ 抓错物料：光「看见」不等于「认对了」

机器人已经能在货架前定位到格口、扫到物料轮廓、规划抓取姿态。但有一个问题始终没被回答：货架上这个格子，放的到底是不是该物料？视觉分不清 0805 和 0603 的电容——两者在相机里几乎一样。这个项目就是给「物料身份」补上一条可校验的凭证链。

契约

一条标签编码三件事

标签格式 FPV:<shelf_id>:<level>:<slot>:<material_id>:<valid_until_epoch>，例如 FPV:SH-002:1:3:MAT-001:1799999999。位置、物料、时效编码在一起，一次读码完成三重校验。

  • 位置校验：读到的是不是机器人要停靠的那个格口
  • 物料校验：这个格口当前该放的是不是任务指定的物料
  • 时效校验：标签/物料信息是否已过期（valid_until=0 表示长期有效）
  • 契约层唯一定义：SlotTag 放在 fpv_core/contracts.py（540 行），各子包一律 import 不重复定义
实现

三后端 + 故障四分离

fpv_perception/slot_tag.py（391 行）实现三个读码后端，共用一套 SlotReader 接口；SlotVerifier 把「读不出」拆成四种性质完全不同的故障。

  • VisionSlotReader 视觉解码 / RfidSlotReader 备选 / SimulatedSlotReader 仿真
  • unreadable 读不到、position_mismatch 位置错、material_mismatch 物料错（最严重）、expired 已过期
  • fault_hint 三提示：no_image_source 指向接线、no_backend 指向缺依赖、decode_failed 指向贴码方式
  • 开发机没装 opencv 也能 import 全部模块跑完测试
闸门

校验不通过就不产生抓取计划

「格口标签校验」节点插在行为树的「视觉检测之后、规划抓取之前」。校验不通过 → 拒绝抓取 → 不产生 grasp_plan。校验与否不再依赖上层自觉，由树结构本身保证。

  • 节点位置在 fpv_bt/factory_bt.py:332，早于「规划抓取」节点
  • 核心用例 test_wrong_material_blocks_grasp 锁死「物料不符时不得抓取」
  • 新增 16 个测试，单元测试总数 49 → 65 全绿
选型

用现场约束倒推方案

方案不是选出来的，是被约束逼出来的：视觉不可靠 → 必须有唯一身份凭证 → 凭证要贴 84 个格口 → 于是「每个格口一个 ESP32 节点」的成本问题浮出水面。

  • 二维码方案零 ESP32：标签 ¥4 + 标签座 ¥40 + 照明 ¥10 ≈ ¥80
  • RFID 方案需 30 个 ESP32 节点，约 ¥1095
  • 成本差 270 倍，且二维码方案复用已有相机

💰 货架端方案选型：成本差 270 倍

先用 RapidOCR 全量识别客户发来的 20 张物料截图，提取商品标题与订单号，确认客户实际没有采购 ESP32——方案缺口由此暴露：货架端是「哑」的。随后比较两套货架端身份方案。

📌 三条可迁移的结论

原则 1

「看见了」和「认对了」是两件事
轮廓识别无法区分同尺寸物料，必须有唯一身份凭证

原则 2

校验要做成闸门，不要做成提示
插在行为树里，不通过就不产生抓取计划

原则 3

故障要分类到可行动的粒度
no_image_source / no_backend / decode_failed 对应三种现场处置
