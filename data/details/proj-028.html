🪐 397.7 万面压到 71.5 万面，然后让它们真的飞起来

原始素材是 7 个二进制 STL，共 397.7 万三角面、189.6 MB——直接丢进浏览器会让整页崩掉。这个项目分两步解决：先写一个 Go 转换器把网格压到能进 GPU 的体量，再把压好的模型组装成一个可交互的太阳系轨道空间站。

第一步

顶点焊接：用位模式哈希

STL 里每个顶点都重复出现多次，必须先焊接。原先按「包围盒 / 100000」量化坐标，结果把 gun 模型 11.8 万面错误并成 2625 个顶点（真实唯一顶点 59434），几何直接毁掉。

  • 根因：量化步长是个无解变量——太小顶点分裂，太大过度合并，且边界顶点会因舍入方向分裂
  • 修复：改用 float32 的位模式（math.Float32bits）做哈希键
  • 理由：STL 内部本就是 float32，同一位置必然同位模式，无损
  • 量化步长这个变量就此消失
第二步

QEM 简化：分层收缩

第一版把 11.8 万面压到 2384 面（只剩 2%），而且看起来成功了——面数确实降了，几何却已崩坏。

  • 根因：塌缩后只为新邻居补候选，候选集迅速枯竭，堆提前耗尽时循环就退出
  • 次因：用「两端邻接面数差 > 8」近似判断边界，把绝大多数边都拒了
  • 修复：每轮重建候选集、按边长排序短边优先、每轮朝目标收拢 15%、最多 40 轮
  • 「面数降了」不等于「几何对了」——必须同时看形状
第三步

导出前剔除退化面

legs 模型有 2 个面三点共线（Y/Z 完全相同），但索引各不相同——所以索引检查抓不到它。

  • 后果：three.js 法线计算会产出 NaN，整个场景崩掉
  • 修复：导出前加 dropDegenerate()，用叉积长度判零面积（eps=1e-14）
  • 这个 bug 是被 gateway_test.go 的抽样体检发现的，不是被主流程发现的
澄清

v/f ≈ 0.5 是健康分布

焊接后顶点面数比只有 0.514，看着偏低，疑似焊接过度。

  • 实际按欧拉公式 V = F/2 + 2，三角面网格的 v/f 天然接近 0.5
  • 这是健康的分布，不是问题
  • 据此把体检阈值从 0.3~3.0 收紧到合理区间——先确认什么是正常，再谈异常

空间站

7 个模型组装成轨道空间站

body 核心舱 / armL-R 太阳翼 / legs 桁架 / gun 桅杆 / hair 天线 / cable 缆线。

  • 站体总高由 13 单位放大到 34 单位（×2.6）

  • 不同步会散成碎片，失去整体感
巡检

「检视模式」自动暂停公转

聚焦任何行星后视野只有约 53 单位高，空间站在 orbit 215 必然在视野外。

  • 站体以 0.075 rad/s 公转 + 垂直 7.5 单位起伏
  • 不暂停的话相机永远在追——那是「人在追狗」
  • 跟随 lerp 0.12 → 0.20（0.12 追不上，实测相机偏离 166 单位）

📏 把「看起来太小」变成可量化的判据

用户反馈「空间站没有显示」。查下来它一直在渲染（复选框勾着、draw call 正常），只是小到无法辨认。这是设计问题，不是 bug——但肉眼只会得出「没显示」的错误结论，量化才能区分「没渲染」和「渲染了但看不见」。

🔢 屏幕像素高度反算

环节 做法 / 数值
全景机位参数 相机 radius 470 / fov 55°，空间站 orbit 215，距离 255~685
可视高度范围 265 ~ 713 单位

💡 可复用经验：这类「看起来太小 / 看不见」的问题，都该用屏幕占比量化，而不是靠描述。判据设计成脚本（station-check.mjs）后，它就成了可回归的自动化检查。

🚧 启动前资产门禁：让崩溃在启动前就暴露

three.js 项目最常见的翻车方式是「页面卡在正在装配」——ES module 静态 import 一旦解析失败，整个模块都不执行，main() 里的 try/catch 全部失效。这类问题在浏览器里几乎无法排查：控制台只留一条 404。

🔧 五项启动前检查 + 路由门禁

检查项 拦下什么
1. importmap 覆盖 裸模块说明符未映射；且前缀映射值必须以 / 结尾
2. 依赖存在 目标文件缺失（如漏下载 OutputShader.js）
3. 完整依赖闭包可解析 vendor 目录结构不符官方布局导致深层 404
4. 具名导入符号确实被导出 用了 7 处 THREE.* 却没 import THREE → ReferenceError
5. 静态资源体积预算 前端资源超预算（模型二进制有独立预算）
路由层门禁 路径穿越 403 + 后缀白名单（仅 .bin/.json）+ 单文件体积预算

💡 实测拦截：..%2f..%2fwin.ini → 403、%2e%2e%2fsecret.txt → 403、shell.exe → 403。注意 ../../etc/passwd 返回 200 是因为 Go http 客户端发送前就归一化了 ..，服务端从未见到穿越路径。

📌 三条可迁移的结论

原则 1

ES module 静态 import 失败 = 整个模块不执行
try/catch 与 .catch() 全部失效，只能靠不依赖 module 的经典脚本守卫兜底

原则 2

写检查器必须按浏览器语义实现
importmap 前缀映射是字符串替换，尾斜杠会被吃掉

原则 3

交互 bug 必须用交互验证
静态截图抓不到聚焦黑屏这类问题
