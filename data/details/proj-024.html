🐛 核心命题：用户说的「加载慢」和「项目不显示」，其实是两个病

用户反馈是三句话：竖屏加载慢、技术能力布局不行、项目区不显示。实测拆开后发现这是两类完全独立的病因：一类在加载链路——一串阻塞把 load 事件拖到 21 秒；另一类在渲染触发条件——一个语义误用让整块项目区永久停在 opacity: 0。

病因 A

加载链路五处阻塞

load 事件实测 21483ms。而 load 要等 CDN 动效库 + Google Fonts + 背景视频全部就绪——其中任意一个挂着，首屏就黑屏。

  • 全屏加载遮罩在等 window.load，且期间 lock body 滚动，用户干瞪眼十几秒
  • DOMContentLoaded 被 defer 的外网脚本阻塞——数据渲染挂在这个事件上
  • fonts.googleapis.com 阻塞式加载，国内可达性差
  • cdnjs.cloudflare.com / cdn.jsdelivr.net 在国内常年挂起，实测始终未完成
  • 技能区 37 个标签平铺混排，看不出技术栈结构
病因 B

阈值语义误用

IntersectionObserver 的 threshold 语义是「相交面积 ÷ 元素自身面积」，不是「占视口多少」。这个除数用错，整块超高元素就永远触发不了。

  • 项目网格高 12646px，手机视口仅 844px
  • 即便元素完全盖住视口，相交比也只有 844/12646 ≈ 6.7%
  • 6.7% < 12% 阈值 → 永远拿不到 .visible → opacity 永久停在 0
  • 视频区只有 3247px（相交比 26%）所以正常显示——这恰好解释了「中间有距离」的错觉：那块其实是空白
修复

加载侧：拆掉所有阻塞

核心思路是让渲染不再依赖任何外部资源的就绪时刻——能提前的提前，能自托管的自托管，能不等的就不等。

  • 全屏遮罩 → 顶部 2px 进度条，不遮挡内容、不锁滚动，DOM 就绪后 120ms 收尾，2.5s 兜底
  • main.js 改为 DOM 解析完毕立即渲染（仅 readyState === 'loading' 时才监听）
  • Google Fonts 改 media="print" onload="this.media='all'" 异步加载 + noscript 兜底
  • GSAP / ScrollTrigger / SplitText / Lenis 四件套自托管，实测合计 134 KB
  • studio.js 改 async 加载，依赖检测从顶层常量改为动态函数，轮询 ≤3 秒后启用动效，超时自动降级
修复

可见性侧：双观察器

按元素高度分流，让「超高元素」和「普通元素」走两套触发策略；同时补一条兜底，杜绝任何因阈值或布局异常导致的空白区块。

  • 超高元素（高 > 1.5 屏）：threshold 0 + rootMargin '0px 0px -15% 0px'，顶端进入视口即触发
  • 普通元素：保留 threshold 0.12，避免过早出现
  • 2.5 秒兜底：仍未 visible 且已滚到可见区则强制显示
  • 窄屏压缩：描述 -webkit-line-clamp 2 行、高亮列表隐藏、技术标签留 3 个 + 「+N」溢出徽章、卡片 padding 28 → 20px

📌 最有价值的一条：为什么之前移动端测试全绿

盲区

headless Chrome 默认 prefers-reduced-motion: reduce
而站点降级规则里恰好有 .reveal { opacity: 1 !important }

后果

强制显示掩盖了「不可见」类 bug
真实手机默认 no-preference，不触发该覆盖

解法

显式 setEmulatedMedia 为 no-preference
自建 reveal_check.py 已内置该模拟，测移动端必须带上
