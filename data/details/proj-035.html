📏 把「写得好」拆成能判红的 34 条闸门

让模型写小说，「写得好」是没法验收的。这个项目的做法是拒绝模糊要求：把质量拆成 34 条可执行的判据（编号 G0–G22），每条有明确阈值，validate() 一次跑完返回结构化问题列表 —— 质量第一次变成能跑测试、能回归的工程问题。

📊 引擎规模

文件 行数 职责
gates.py 412 34 条闸门判据 + 四档 profile 阈值
model.py 280 Chapter / Scene / Block 数据模型与解析渲染
writer.py 106 正文组装
cli.py 102 check / build / voice 三条命令
核心合计 915 行 对外只暴露 parse / validate / render / render_voice_script 四件事

💡 接口窄是刻意的：对外只暴露四个函数，内部怎么演进都不会影响调用方，也让「校验」与「生成」彻底分离。

🚦 闸门怎么设计：判据、标签与四档阈值

闸门分三层信息：编号（G0–G22）用于定位，标签（如 G16-chron-year）用于报告，阈值按体裁档位取值。34 条判据里有的一档一检，有的按档位换阈值 —— 但判据本身只有一份。

🚧 判据分布（节选）

闸门 判据 意图
G0 / G13 正文为空 / 字数下限 1100 挡住空稿与半截稿
G1 / G1b 对话字数占比 / 台词块占比（按档） 保证「用对话推剧情」而非叙述独白
G2 / G3 每场至少一句台词 / 有 time_anchor 与 location 且首段旁白落地点名 防止场景漂在空中
G4 / G4b 每个在场角色的服装落进旁白 / 属性细节也要落字（warn） 把设定表变成正文里的具体字
G5 / G6 旁白带后果的动作词 ≥3 / 全章有距离词与视线词 避免「静止说明」式行文
G7 旁白不许评价（心里想 / 不禁 / 显然 / 五味杂陈…） 禁止替读者下结论
G8 / G9 连续旁白数 / 单段旁白长度（按档） 控制旁白与台词的节奏配比
G11 / G12 章尾有问句或悬停 / 说话人必须在名单内 章尾有钩子，角色不越界
G15 台词均长 ≤16 防为凑字数拉长句子
G16 编年块必须带年份且年份单调（倒叙要标【倒叙】） 挡住时间线错乱
G17 / G18 群像换人说话要交代是谁 / 动作节拍数（施动者 + 动作 + 物理结果） 多人物与动作场面可核查
G19 / G20 / G21 每场须有 emotion 声明 / 情绪须写明起点→终点且不能整章全平 / 旁白至少两种身体信号且分在两段以上 情绪不能只在文档里存在
G22 台词留白率（……／——）≥8% 所有人说话都完整，说明没一件事说不出口

💡 G21 的写法很关键：旁白不许写「她很难过」，只能让身体漏出来 —— 至少两种信号、分在两段以上。这条把「情绪描写」从形容词换成了可检测的物理信号。

四档

档位只改阈值

PROFILES 里 dialogue / ensemble / chronicle / action 四档，每档给不同的对话占比区间、旁白长度上限与动作节拍数，判据本身完全相同。

  • 新增体裁不需要复制一份闸门代码
  • 判据与阈值分离，改阈值不影响判据语义
情绪

情绪三条件必须同时成立

每条情绪线要同时满足：有起点与终点（G20）、有可观察的出口（G21）、台词自己也带（G22）。legacy 模式把 G19/G22 降级为 warn，但不豁免、不静默。

  • 整章情绪全平直接判红
  • 历史稿过渡开关明确留痕，新稿禁用
输出

结构化 Issue 列表

validate() 返回的每个 Issue 都带闸门标签、级别（error / warn）与具体消息，不是一句「不合格」。

  • 标签可直接定位到对应判据
  • warn 与 error 分级，不把建议当错误

🧪 测试用反例：闸门永远绿等于没有闸门

如果只用「好稿子」当测试样本，闸门永远绿，测不出任何东西。所以测试集全部是能判红的反例 —— 每种闸门都要有一条能把它打红。

📕 实跑产出：全部指标可复算

《第七个证人》是这个引擎的第一个完整实跑样本 —— 5 章全部过闸，产出的每一项指标都能从产物里复算出来。

交付

两条命令两件产物

cli build 产出人读的全书.md（多场之间用 ◇ 分隔）；cli voice 产出配音表.json，台词一句一条、旁白一段一条，直接可喂 TTS。

  • 配音表实测 312 条
  • 每条带 voice / text / kind / chapter 四个字段
评估

人物声音画像

评估报告给出每个角色的句数、均长、问句率与常见开头，例如纪云舒 104 句均长 9.4 字问句率 6%，陆守成 25 句均长 18.3 字问句率 0%。

  • 还给出旁白与台词的高频三字组指纹
  • 模板化用词（如「了一下」出现 20 次）能被看见
盲区

已知不覆盖写进文档

判据体系的边界自己写清楚：G4 只比对有限词表、G6 只在旁白里找视线词、G22 可被大量省略号喂饱且不含字数校验、抓不到跨年时间线矛盾（如 1998 年的铁盒里装着 2015 年的收费单）。

  • 盲区进入「已知不覆盖」清单，作为迭代入口
  • 不假装覆盖了做不到的事

📌 三条可迁移的结论

原则 1

把主观要求拆成可判红的判据
模糊要求无法验收，编号判据可以

原则 2

测试必须用反例
只用好样本，闸门永远绿

原则 3

判据与阈值分离
加体裁只改阈值，不复制判据
